# CLOAKID — Project Milestones

## Purpose

This document defines the proposed milestones for the CLOAKID project. Each milestone has a deliverable and completion criteria so that the team can track progress consistently.

Exact dates should be added after the team confirms its academic schedule and submission deadline.

## Milestone 1: Requirements Review

**Activities**
- Review the CLOAKID SRS.
- Confirm project objectives and scope.
- Identify functional and non-functional requirements.
- Clarify ambiguous requirements.

**Deliverables**
- Reviewed SRS.
- Organized requirements documentation.
- List of unresolved questions, if any.

**Completion criteria**
- Requirements are understandable and traceable to the SRS.
- Unresolved issues are documented for team discussion.

**Status:** Not started / In progress / Complete

## Milestone 2: Project Documentation

**Activities**
- Review the project context and definitions.
- Organize references and planning documents.
- Establish documentation conventions.
- Organize the GitHub repository.

**Deliverables**
- Project foundation documents.
- Project planning document.
- Organized repository structure.

**Completion criteria**
- Relevant existing documents are preserved.
- File names and locations are consistent.
- No unnecessary duplicate documents are introduced.

**Status:** Not started / In progress / Complete

## Milestone 3: System Architecture and Design

**Activities**
- Identify major system components.
- Describe component responsibilities and interactions.
- Prepare an architecture diagram if useful.
- Review the design against the SRS.

**Deliverables**
- Architecture documentation.
- System architecture diagram, if required.

**Completion criteria**
- The proposed design addresses the approved requirements.
- Components and their relationships are clearly explained.
- No unsupported features are presented as confirmed functionality.

**Status:** Not started / In progress / Complete

## Milestone 4: Security and Privacy Review

**Activities**
- Identify relevant security and privacy risks.
- Review how the proposed design addresses those risks.
- Document appropriate safeguards.
- Prepare a threat-model diagram if useful.

**Deliverables**
- Security and privacy documentation.
- Threat-model diagram, if required.

**Completion criteria**
- Relevant risks and proposed mitigations are documented.
- Security decisions are consistent with the SRS.
- Remaining concerns are recorded for further review.

**Status:** Not started / In progress / Complete

## Milestone 5: Implementation

**Activities**
- Implement the approved system requirements.
- Follow the agreed project structure and coding conventions.
- Track implementation progress.
- Document important technical decisions.

**Deliverables**
- Implemented project components.
- Source code and supporting documentation.

**Completion criteria**
- Planned functionality is implemented to the extent required for the project stage.
- Changes are committed to the appropriate branches.
- Outstanding implementation issues are documented.

**Status:** Not started / In progress / Complete

## Milestone 6: Testing and Validation

**Activities**
- Prepare test cases based on requirements.
- Test normal and relevant failure scenarios.
- Verify security-related requirements where applicable.
- Record and resolve defects.

**Deliverables**
- Test cases and results.
- Defect list, if applicable.
- Updated implementation and documentation.

**Completion criteria**
- Required test cases have been executed.
- Results and unresolved defects are recorded.
- Critical failures are addressed before final submission, according to project requirements.

**Status:** Not started / In progress / Complete

## Milestone 7: Final Review and Submission

**Activities**
- Review the completed project against the SRS.
- Check documentation consistency.
- Review and merge approved GitHub changes.
- Prepare required submission materials and demonstration.

**Deliverables**
- Reviewed project repository.
- Final documentation.
- Required submission materials.

**Completion criteria**
- Required deliverables are present.
- Documentation matches the final project state.
- Outstanding limitations are disclosed.
- The team has verified the submission requirements.

**Status:** Not started / In progress / Complete
